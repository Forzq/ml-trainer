# ML Trainer

Windows-приложение для подготовки к собеседованиям по машинному обучению. Карточки по темам, чат, голосовой ввод через Deepgram с резервом OpenAI Whisper, озвучка Fish Audio, проверка через OpenRouter и векторная база Qdrant.

Пять разделов: **Классический ML, Data Science, NLP, CV, DL**. Сейчас доступны **500 вопросов — по 100 в каждой теме**. В каждом разделе 40 Junior, 40 Middle и 20 Senior. У каждой карточки есть сложность, эталонный ответ и три критерия проверки. Полные списки: [Классический ML](../content/classical-ml.md), [Data Science](../content/data-science.md), [NLP](../content/nlp.md), [CV](../content/cv.md), [DL](../content/dl.md). Описание банка и источников — [content/README.md](../content/README.md). Это подборка типовых тем интервью, а не статистический рейтинг частоты конкретных вопросов.

Сложность можно выбрать перед началом тренировки и отфильтровать в библиотеке. Размер тренировки — от 2 до 20 вопросов. В режиме «Все темы» разделы чередуются: при достаточном числе карточек количество вопросов из разных тем отличается максимум на один. Внутри темы сначала предлагаются менее отработанные карточки выбранного уровня; при равных условиях первым идёт менее отработанный раздел, чтобы короткие тренировки тоже охватывали разные темы. Старые шесть карточек сохранили ID, ответы и обсуждения остаются доступны.

## Запуск приложения

Дважды нажмите **ML Trainer.lnk** на рабочем столе / в папке проекта или **Start.vbs**. Открывается собственное Windows-окно с иконкой на панели задач, без браузера, адресной строки и консоли. Повторное нажатие ярлыка поднимает уже открытое окно.

Закройте окно крестиком или нажмите **Подключения → Остановить приложение**. Приложение завершит запущенный им сервер и освободит базу. Если сервер был отдельно запущен разработчиком, закрытие окна его не остановит. Логи: `logs/desktop.log` и `logs/server.log`.

Оболочка использует **pywebview + Microsoft Edge WebView2 Runtime**: это встроенный компонент отображения интерфейса внутри WinForms-окна. Приложение не запускает Edge или Chrome. При отсутствии компонента установите [WebView2 Evergreen Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/). Запуск выполняется через виртуальное окружение Python; отдельный автономный EXE / установщик ещё не собран.

По умолчанию включена тёмная тема с фиолетовыми акцентами. Кнопка солнца / луны справа вверху переключает светлую и тёмную темы. Выбор сохраняется в профиле приложения; оформление рамки Windows также переключается, если это поддерживает версия ОС.

На другом Windows-компьютере сначала установите Python 3.11+ и запустите `Setup.cmd`. Установка зависимостей требует интернета. При переносе папки заново выполните настройку: виртуальное окружение и ярлыки содержат абсолютные пути.

Для создания ярлыка на рабочем столе:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/create-shortcut.ps1 -DesktopShortcut
```

## Что работает без ключей

- Банк из 500 вопросов по пяти направлениям и трём уровням сложности.
- Тренировки по выбранной теме или всему банку, пропуск, объяснение и итоги.
- Ответы текстом; черновики сохраняются в отдельном профиле приложения `data/desktop-profile/`.
- **Демо-проверка по ключевым словам**, явно обозначенная в интерфейсе. Она не оценивает смысл и может ошибаться, в том числе на отрицаниях.
- Системная озвучка через SpeechSynthesis внутри WebView2 при `TTS_PROVIDER=system`. Наличие и качество русского голоса зависят от системы. Для выбранного голоса Fish Audio нужен отдельный ключ.
- Векторный поиск в Qdrant, фильтрация по метаданным темы.
- История сессий и ответов, сохраняющаяся после перезапуска: страницы по 30 тренировок и общие счётчики за всё время на главной.

## Подключение API

Скопируйте `.env.example` в `.env` и заполните:

```dotenv
DEEPGRAM_API_KEY=...
OPENROUTER_API_KEY=...
OPENROUTER_MODEL=идентификатор-модели-из-openrouter
```

Для резервного распознавания добавьте в `.env`:

```dotenv
OPENAI_API_KEY=ключ-OpenAI
OPENAI_TRANSCRIPTION_MODEL=whisper-1
```

Сначала запись распознаёт Deepgram. При ошибке сети, таймауте, отказе API или некорректном ответе та же запись один раз отправляется в OpenAI Whisper. Если настроен только `OPENAI_API_KEY`, Whisper используется сразу. Успешная пустая расшифровка не запускает резерв. С ключом резерва таймаут ответа Deepgram сокращается до 30 секунд; для Whisper — 90 секунд. После любого распознавания работает обычная очистка через OpenRouter, а интерфейс сообщает, если использован Whisper. Ключ OpenAI хранится только на сервере.

Для `whisper-1` [объявлено отключение 26 февраля 2027 года](https://developers.openai.com/api/docs/deprecations). Модель можно сменить через `OPENAI_TRANSCRIPTION_MODEL`; используется OpenAI Audio Transcriptions API с JSON-ответом.

Закройте приложение и снова откройте ярлык. Модель должна поддерживать `response_format: json_object`. API-ключи загружаются только сервером, `.env` исключён из Git.

**Голос:** нажмите «Ответить голосом», разрешите микрофон, затем «Закончить запись». После этого запись отправится в Deepgram Nova-3 (`language=multi`) или в настроенный резерв OpenAI Whisper. Если подключён OpenRouter, расшифровка проходит дополнительную очистку. По умолчанию используется `OPENROUTER_MODEL`, но редактору можно назначить отдельную быструю модель через `OPENROUTER_TRANSCRIPTION_MODEL`; проверка знаний и обсуждение продолжают использовать `OPENROUTER_MODEL`. Ключ OpenRouter общий. Редактор убирает «ээ», «эм» и явные запинки, добавляет пунктуацию и восстанавливает очевидно искажённые ML-термины: например, `rock aug / pr aug` → `ROC-AUC / PR-AUC`.

Для отдельного редактора в `.env`:

```dotenv
OPENROUTER_TRANSCRIPTION_MODEL=google/gemini-3.1-flash-lite
```

Пустое значение возвращает очистку к основной модели. В локальном сравнении 15 ноября 2026 Gemini 3.1 Flash-Lite прошла три проверки сохранения смысла за 0,85–1,07 секунды; текущая DeepSeek — за 1,52–2,33 секунды. Это полное время дополнительных запросов на коротких примерах с учётом сети, а не гарантия скорости или точности на любых ответах. Изменение применяется после перезапуска приложения.

Редактору запрещено дополнять ответ, исправлять ошибки в знаниях и подменять сомнения уверенностью. Он получает только исходную расшифровку и публичный контекст текущего вопроса (вопрос, тема, теги); эталон, критерии оценки и разбор ему не передаются. Неоднозначные фрагменты должны сохраняться. Самому тренеру также задано оценивать смысл и не считать понятные опечатки ошибкой в знаниях. Обработка моделью всё же может ошибаться: очищенный текст остаётся редактируемым перед отправкой, а под полем можно раскрыть исходную расшифровку последней записи и сравнить изменения. Это работает и при первоначальном ответе, и в обсуждении. Текст, набранный вручную, не проходит очистку.

При недоступности OpenRouter или некорректном ответе редактора исходная расшифровка остаётся в поле, появляется сообщение «очистка недоступна». Без настроенного OpenRouter используется обычная расшифровка сервиса распознавания. Пустая запись не отправляется редактору. Очистка добавляет один запрос OpenRouter по текущему тарифу и время его выполнения (таймаут — 35 секунд), после неё проверка ответа запускается отдельной кнопкой. Проверьте текст, при необходимости исправьте и нажмите «Проверить ответ» / «Отправить».

Максимум — 2 минуты / 20 МБ. При завершении записи, уходе с экрана или закрытии окна микрофон освобождается. В обычном режиме начало и конец записи задаются кнопками. В Live Training конец реплики определяется автоматически; распознавание в обоих режимах пока пакетное, без поточной расшифровки и перебивания речи тренера.

**Live Training:** в окне новой тренировки выберите режим «Live Training · полностью голосом», тему, сложность и число вопросов. В уже открытой тренировке можно нажать «Включить Live». После первого старта и разрешения микрофона цикл автоматический: озвучка вопроса → запись ответа → распознавание и очистка → проверка → озвучка разбора. Текст вопроса, ответа и разбора отображается в том же чате и сохраняется обычным способом.

Микрофон включается только после завершения озвучки, с небольшой паузой на затухание звука. После разбора есть **6 секунд на уточнение**: можно возразить или задать вопрос, и тренер продолжит обсуждение той же карточки. Если речь не началась, приложение автоматически переходит дальше; после последней карточки показывает итоги. Начальный ответ при полном молчании не отправляется и вопрос не пропускается: через 25 секунд режим ставится на паузу.

Конец ответа определяется **локально по уровню звука**, без отдельной модели VAD: при устойчивом сигнале фиксируется начало речи, затем пауза 1,8 / 3 / 5 секунд завершает запись. Длительность паузы и чувствительность выбираются при старте; по умолчанию 3 секунды и обычная чувствительность. Это MVP-детектор: шум может приниматься за речь, а тихая речь — не обнаруживаться. Для длинных размышлений выберите паузу 5 секунд, при акустическом эхо полезны наушники. Каждый законченный фрагмент отправляется в настроенное распознавание Deepgram / резерв Whisper, затем в очистку OpenRouter; новых ключей не требуется. Голосовые команды также проходят распознавание, поэтому используют API.

Команды работают, **когда тренер слушает**: «повтори вопрос», «повтори разбор», «следующий вопрос», «не знаю», «пауза» / «стоп», «заверши тренировку». Команда определяется по целой короткой реплике, а не по слову внутри содержательного ответа. «Не знаю» отмечает вопрос пропущенным и озвучивает ориентир. Во время речи тренера доступны кнопки остановки и паузы; голосовое перебивание пока не реализовано. На паузе микрофон полностью выключается, для возобновления нужна кнопка «Продолжить». «Обычный режим» сохраняет текущую карточку и возвращает ручное управление.

При ошибке TTS, распознавания, очистки или проверки автоматическое продолжение приостанавливается; уже распознанный ответ остаётся в черновике. Отмена во время запроса не запускает запоздалую озвучку или отправку. Уже отправленная проверка может завершиться и сохранить разбор, но цепочка не продолжится до явного возобновления. При обновлении страницы или повторном запуске Live не включает микрофон сам: режим запускается заново явным действием. На данный момент выбор режима относится к текущему окну, отдельной записи режима в истории нет.

Разрешение запрашивается собственным Windows-диалогом при первом обращении к микрофону в текущем запуске. Доступ к камере не выдаётся. Если запись недоступна, проверьте **Параметры Windows → Конфиденциальность и безопасность → Микрофон → Разрешить классическим приложениям доступ к микрофону**.

**Проверка:** OpenRouter получает текст вопроса, критерии, эталон и ответ ученика. Модель возвращает оценку, покрытые и пропущенные критерии, текст разбора. При ошибке провайдера ответ остаётся в поле ввода; скрытого переключения на демо нет.

**Обсуждение после разбора:** поле ввода и микрофон остаются доступны. Можно задавать уточнения, приводить контрпримеры и спорить с замечаниями тренера. Модель получает вопрос, критерии, первоначальный ответ и разбор, а также недавние реплики обсуждения. Она должна перепроверять замечания и признавать ошибки в объяснении, если аргумент ученика верен. Исходный балл за первую попытку автоматически не пересчитывается.

Только кнопка **«Следующий вопрос»** переключает карточку и открывает новый чат. Последний вопрос также можно обсуждать до нажатия **«Итоги тренировки»**. Обсуждения всех карточек сохраняются в SQLite и доступны в итогах / истории; после перезапуска восстанавливается активный вопрос и его переписка. Черновики первоначального ответа и обсуждения хранятся раздельно. В демо-режиме диалог честно обозначен как демо: показывается эталон, без имитации полноценного понимания.

Полная переписка сохраняется локально; в запросы к LLM отправляются исходный контекст и до 24 000 символов недавних пар сообщений. При обновлении старая история автоматически дополняется таблицей обсуждений и указателем текущего вопроса, без удаления ответов.

Для одной реальной проверки обсуждения с синтетическим возражением используйте `python scripts/check-discussion.py`. Команда обращается к OpenRouter с текущими настройками, сохраняет ответ в `logs/discussion-check.json` и не меняет реальные сессии.

Для проверки очистки выполните `python scripts/check-transcription.py`: это три реальных запроса OpenRouter на искусственных примерах с ROC-AUC / PR-AUC и ошибочными определениями. Результаты сохраняются в `logs/transcription-check.json`; проверяется, что редактор убирает паузы и исправляет названия, сохраняя сомнения и ошибки в знаниях. Для сравнения укажите `--model идентификатор` несколько раз: по три реальных запроса на каждую модель, результат в `logs/transcription-benchmark.json`. Реальные записи и тренировки этот сценарий не затрагивает.

**Озвучка Fish Audio:** в `.env` добавьте:

```dotenv
TTS_PROVIDER=fish
FISH_AUDIO_API_KEY=твой_ключ_fish_audio
FISH_AUDIO_VOICE_ID=1db1618b6eaf4571ac7db70e20eb6727
FISH_AUDIO_MODEL=s2.1-pro-free
FISH_AUDIO_LATENCY=low
```

Выбран голос «Марин китагава», русский. Закройте приложение и снова запустите ярлык. В **Подключения → Послушать голос** можно проверить озвучку без начала тренировки; эта кнопка работает и при выключенном звуке тренировки. Во время загрузки и воспроизведения справа вверху отображается кнопка остановки. В диалоге подключения кнопка прослушивания также превращается в кнопку остановки.

Справа вверху есть **Настройки голоса**: громкость от 0 до 100% и переключатель автоматической озвучки. Уровень сохраняется между запусками и меняет громкость уже воспроизводимого аудио Fish Audio без нового запроса. По умолчанию автоозвучка включена: после «Проверить ответ» разбор начинает звучать сразу после его получения и синтеза, без нажатия на динамик. Кнопка динамика у сообщения остаётся для повторного прослушивания и работает даже при выключенной автоозвучке. При громкости 0% новые запросы озвучки не отправляются.

Там же доступна **Интонация**: естественная, спокойная, очень спокойно и медленно (Very calm and slowly), дружелюбная, энергичная, мягкая и шёпот. Выбор сохраняется в профиле и применяется к следующей озвучке. Кнопка «Послушать интонацию» позволяет сравнить варианты на одной фразе. Смена интонации останавливает текущую запись, но сама не создаёт API-запрос; новый запрос выполняется при следующем воспроизведении. В кэше разные интонации хранятся отдельно. Для Fish S2 передаются управляющие подсказки вида `[calm]` и `[very calm and slowly]` только в TTS-запросе; текст разбора в чате остаётся прежним. Это указания модели, а не точная регулировка высоты голоса: выраженность эффекта зависит от текста и выбранного тембра. Системная озвучка Windows эти настройки не поддерживает.

В Fish Audio передаётся текст вопроса или разбора, который виден в чате, с выбранной подсказкой интонации. MP3 передаётся потоком через локальный сервер и MediaSource: Windows-приложение начинает воспроизведение после получения первых аудиофрагментов, пока остальная запись ещё генерируется. В движках без поддержки MP3 в MediaSource используется загрузка целого файла. Текст LLM пока приходит целиком; потоковая озвучка сокращает ожидание после его получения.

По умолчанию `FISH_AUDIO_LATENCY=low` и размер фрагмента синтеза — 100 символов. Варианты `balanced` (200) и `normal` (300) дают модели больше контекста для связной интонации, но могут увеличить начальную задержку. Если на границах фраз заметны изменения подачи, попробуйте `balanced` и перезапустите приложение. Бесплатный `s2.1-pro-free` не гарантирует задержку: очередь на стороне сервиса остаётся вне контроля приложения.

Повторные фразы берутся из ограниченного кэша в памяти сервера: до 32 записей / 16 МБ. При вытеснении или перезапуске запрос понадобится заново. Разные тексты не ждут общего замка синтеза; одинаковые одновременно запрошенные фразы объединяются. При переходе на другой экран, выключении звука или начале записи микрофона озвучка останавливается, получение потока отменяется. Незавершённая запись не кэшируется. Запоздалый ответ сервиса после отмены не запускает звук.

Ключ Fish Audio остаётся на сервере. При ошибке ключа, доступа к голосу, баланса, лимита или сети приложение показывает причину. Скрытого переключения на другой голос или платную модель нет. Чтобы вернуться к системному голосу, явно установите `TTS_PROVIDER=system`.

По [условиям Fish Audio](https://fish.audio/blog/s2-1-pro-free-api/), проверенным 15 ноября 2026, `s2.1-pro-free` доступна бесплатно до 30 ноября 2026 с ограничениями fair use. Доступность и условия могут измениться. Платные `s2.1-pro`, `s2-pro` и `drama-3` включаются только явной настройкой `FISH_AUDIO_MODEL`. Неизвестное имя модели отклоняется приложением, поскольку Fish может заменить его платной моделью по умолчанию.

Проверка одного реального запроса (использует ключ, отправляет короткую фразу и сохраняет MP3 в `logs/fish-voice-test.mp3`):

```powershell
.\.venv\Scripts\python.exe scripts/check-fish.py
```

Для сравнения задержки `normal` и `low`: `python scripts/check-fish.py --compare-latency`. Команда делает **два реальных запроса**, допускает только явно выбранную бесплатную модель и сохраняет время первых данных / полной генерации в `logs/speech-benchmark.json`. Это отдельные замеры с учётом сети и текущей нагрузки, а не гарантия скорости.

## Как проверяется ответ

При создании тренировки выбираются **уровень собеседования** (по умолчанию Middle) и отдельно сложность вопросов. Уровень кандидата, тема и уровень конкретного вопроса передаются проверяющей модели и сохраняются вместе с тренировкой. Базовый вопрос не требует от кандидата перечислить все углублённые детали темы.

В каждой из 500 карточек определены основные критерии с постоянными весами, сумма которых равна 100. В большинстве карточек исходные критерии получили равные или максимально близкие веса; в 17 пересмотренных карточках уточнены формулировки, веса и границы обязательного ответа. Необязательные вопросы отображаются под заголовком **«Углубление · не влияет на балл»**, не включаются в основную озвучку и не являются условием полного балла. Их можно обсудить после разбора.

Модель возвращает для каждого критерия **«Верно»**, **«Частично верно»**, **«Неверно»** или **«Не отвечено»**, короткое подтверждение из ответа и степень выполнения от 0 до 4. Для частичного выполнения доступны 1/4, 1/2 и 3/4 веса. Приложение проверяет соответствие статуса, полноту списка ID и типы значений, затем само рассчитывает баллы. Сумма округляется до целого только в конце. Общий балл от LLM не принимается. В разборе и истории можно открыть **«Разбор по критериям»** и увидеть начисленные баллы и основания.

Проверяющая модель оценивает смысл, допускает эквивалентные объяснения и отличает пропуск от неверного утверждения. Ошибки распознавания и разговорный стиль не должны снижать оценку. Программная проверка делает расчёт прозрачным, но сама по себе не гарантирует, что семантическое решение LLM всегда верно; спорные замечания можно обсуждать в чате.

Новые тренировки хранят снимки заданных вопросов и рубрик. Для старой истории сохраняются прежние формулировки из `content/question-versions-v1.json`; старые оценки автоматически не пересчитываются. В новых AI-разборах записаны модель, версия промпта и версия рубрики. После обновления приложения начни новую тренировку, чтобы получить пересмотренные формулировки.

## 2D-аватар тренера

Встроен готовый аватар **«Ментор по ML»** — образ Марин Китагава из «Эта фарфоровая кукла влюбилась». Он доступен в меню голоса → **«Аватар тренера» → «Ментор по ML»** и выбран по умолчанию, если свои кадры ещё не загружались. Портрет и одежда остаются на постоянном слое. Поверх анимируются небольшие области глаз и рта: внимательный взгляд, размышление, одобрение, спокойное объяснение, моргание и движение губ по звуку. Смена выражения происходит через короткое моргание, без наложения разных пар глаз. Есть лёгкое дыхание; системное предпочтение уменьшения движения отключает дыхание и моргание.

Семь исходных PNG с прозрачным фоном сгенерированы встроенным imagegen из одного базового портрета. Они находятся в `web/avatars/marin/`, параметры совмещения слоёв — в `manifest.json`, набор промптов — в `prompts.json`. Во время тренировок генерация изображений и внешние запросы для аватара не выполняются. Выбор персонажа хранится локально и не удаляет загруженные пользователем картинки.

Чтобы поставить другого персонажа, выбери **«Свои картинки»**.

В меню голоса справа вверху открой **«Аватар тренера»**. В тренировке эта же настройка доступна рядом с персонажем. Загрузи две основные картинки одного персонажа с одинаковым расположением: **рот закрыт** и **рот открыт**. Поддерживаются PNG, JPG и WebP; для прозрачного фона лучше PNG. Исходный файл ограничен 20 МБ, картинки автоматически преобразуются в PNG и уменьшаются до 2048 пикселей. Лимит сохранённого кадра — 6 МБ.

Дополнительные пары для состояний **«Слушает»**, **«Думает»**, **«Одобряет»** и **«Объясняет»** необязательны. Без закрытого кадра нужной эмоции используются основные картинки; без открытого кадра эмоции её изображение остаётся неподвижным. «Одобряет» применяется при AI-оценке от 70 баллов, остальные разборы показывают «Объясняет». Реакции определяются состоянием тренировки и сохранённой оценкой, без отдельного запроса к LLM.

Во время воспроизведения Fish Audio рот открывается по энергии реального аудио и закрывается в паузах, после завершения и при остановке. Для своих картинок используются два кадра, у Марин дополнительно сглаживается степень открытия рта. Это синхронизация по звуку, без отдельных форм губ для фонем. Системная озвучка Windows не предоставляет приложению аудиопоток для такого анализа: реакции работают, рот остаётся закрытым. Выбор «Показывать аватар» сохраняется в профиле. Во время Live Training открытие настроек аватара ставит тренировку на паузу.

Картинки хранятся в `data/avatar/` на этом компьютере, отдельно от базы вопросов, и не отправляются в Fish Audio, OpenRouter или другие внешние сервисы. Изменение картинок не требует перезапуска. Базовая версия работает без дополнительных API-ключей и моделей.

## Векторная база и embeddings

Qdrant работает в persistent local mode через официальный `qdrant-client`. Данные — `data/qdrant/`. Docker и отдельный сервер для старта не нужны. Карточки хранятся как payload вместе с векторами, поиск использует cosine similarity; тема — payload filter. Выбор карточек учитывает число предыдущих попыток.

Для автономной болванки используется стабильный **feature hashing по символьным n-граммам**, 768 измерений. Это векторный поиск, но **лексический, не семантический**: модель не загружается, синонимы не понимаются. Демо-оценка ответа не использует векторное расстояние.

Для семантического поиска укажите доступную в OpenRouter модель embeddings:

```dotenv
OPENROUTER_EMBEDDING_MODEL=идентификатор-мультиязычной-модели
```

При следующем запуске карточки индексируются в отдельную коллекцию. Для каждой модели своё имя коллекции; смешивания разных пространств векторов нет. Неизменившийся банк повторно не векторизуется. Смена модели не удаляет старую коллекцию. При изменении размерности под тем же именем модели нужна новая коллекция / версия модели.

Для перехода на отдельный Qdrant Server или Cloud:

```dotenv
QDRANT_URL=http://localhost:6333
QDRANT_API_KEY=
```

Карточки при первом запуске будут загружены из seed-файла. История остаётся в SQLite. Local mode удобен для одного процесса и маленького банка; для многопользовательского проекта используйте сервер Qdrant и полноценную БД сессий.

## Структура

```text
app/server.py          FastAPI, сессии, распознавание и локальный API
app/store.py           Qdrant и история SQLite
app/embeddings.py      Offline hashing / OpenRouter embeddings
app/trainer.py         Демо-проверка / LLM через OpenRouter
app/recognition.py     Распознавание Deepgram / резерв OpenAI Whisper
app/transcription.py   Очистка расшифровки отдельной быстрой LLM / основной моделью
app/speech.py          Fish Audio TTS, ошибки провайдера и ограниченный кэш
content/questions.json Вопросы, темы, эталоны и критерии
web/                   Интерфейс без сборки и внешних CDN
launcher.pyw           Точка входа Windows-приложения
app/desktop.py         WinForms/WebView2, микрофон, один экземпляр, жизненный цикл сервера
scripts/               Установка и создание ярлыков
tests/                 Сценарии API и проверки хранения
```

Для новой карточки добавьте запись с уникальным числовым `id` в `content/questions.json`. Схема и темы заданы в `app/catalog.py`; допустимые уровни — Junior, Middle и Senior. Проверяются обязательные поля, уникальность ID и формулировок, согласованность тем. При запуске банк синхронизируется с активной коллекцией: embeddings вычисляются только для новых карточек или изменений в индексируемом тексте. Изменения только в эталоне, критериях или сложности обновляют payload без новых векторов; повторный запуск без изменений не обращается за embeddings. Запросы embeddings идут пакетами до 64 текстов с проверкой индексов и сохранением порядка. Не меняйте ID карточек, по которым уже есть история.

Для явного импорта закройте приложение и выполните `python scripts/sync-questions.py`: локальные Qdrant и SQLite копируются в `data/backups/`, затем проверяются сохранённые карточки, поисковый запрос и неизменность существующей истории. Отчёт — `logs/question-import.json`. Команда использует настройки embeddings из `.env`; при семантическом режиме обращается к OpenRouter. Библиотека и поиск учитывают весь банк, включая каталоги более 100 карточек.

## Разработка и проверка

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/check-ui.py
.\.venv\Scripts\python.exe scripts/check-desktop.py
node scripts/check-live-unit.js
.\.venv\Scripts\python.exe scripts/check-live.py
.\.venv\Scripts\python.exe scripts/check-live.py --desktop
.\.venv\Scripts\python.exe scripts/check-avatar.py
.\.venv\Scripts\python.exe scripts/check-avatar.py --desktop
.\.venv\Scripts\python.exe scripts/check-rubric-ui.py
.\.venv\Scripts\python.exe -m app.server
```

Проверка интерфейса использует установленный Microsoft Edge в headless-режиме и отдельную временную базу. Скриншоты сохраняются в `logs/preview-*.png`. Аудиоустройство и ответ распознавания в этой проверке тестовые; реальные вызовы Deepgram, OpenAI Whisper и OpenRouter требуют ключей.

`check-desktop.py` проверяет тот же сценарий в настоящем Windows-окне WebView2: запуск тренировки, текстовый ответ, нативный обработчик разрешения микрофона, тестовую запись, освобождение устройства и закрытие через Python-мост. База и профиль для проверки отдельные. Этот тест нужно запускать в интерактивной Windows-сессии, последовательно с pytest. Профиль старого браузерного варианта не переносится автоматически; база Qdrant и история тренировок остаются на прежнем месте.

`check-live-unit.js` проверяет временные правила окончания речи, команды, отмену и ошибки автоматики. `check-live.py` использует настоящие Web Audio и MediaRecorder с управляемым синтетическим микрофоном: проходит два вопроса без нажатия кнопок после старта, обсуждение, голосовые next/skip, итоги, остановку и ошибки. Озвучка и распознавание имитируются, внешние API не вызываются, база отдельная. Вариант `--desktop` выполняет тот же сценарий в реальном WebView2.

Обычные тесты используют имитацию Fish Audio и не тратят API-баланс. Для проверки воспроизведения реальной записи, полученной предыдущей командой, используйте `python scripts/check-desktop.py --audio logs/fish-voice-test.mp3`; этот сценарий воспроизводит готовый файл и не создаёт новых запросов Fish Audio. Также он удерживает окончание MP3-потока до начала воспроизведения, проверяет звук до конца загрузки и отмену незавершённого потока в настоящем WebView2.

Сервер слушает только `127.0.0.1:8765`. Проверки Host, Origin и локальный токен защищают изменяющие запросы от случайных обращений других сайтов. Это персональное приложение без аккаунтов и производственной авторизации; не публикуйте его сервер напрямую в интернет.

История хранит текст ответов и разборов в `data/history.sqlite3`; аудио тренировки на диск не сохраняется (диагностический `check-fish.py` отдельно сохраняет тестовый MP3). Для распознавания запись отправляется в Deepgram или OpenAI Whisper по правилам резерва. Для очистки через OpenRouter передаются исходная расшифровка и публичный контекст вопроса, для оценки — отправленный учеником текст и критерии, а при семантическом поиске ещё тексты карточек и поисковых запросов. Для Fish Audio отправляются тексты озвучиваемых вопросов и разборов. Каталоги данных, логов, виртуальное окружение и секреты исключены из Git.

`check-avatar.py` проверяет выбор файлов через интерфейс, локальное хранение, сохранение видимости, реакции и переключение кадров по настоящему звуку с паузами. Вариант `--desktop` использует Windows/WebView2, `--audio путь.mp3` дополнительно проверяет потоковое воспроизведение MP3. Внешние API не вызываются, история и картинки пользователя не затрагиваются.

## Как оценить модель-оценщик

Подготовлены 88 синтетических черновых ответов на 11 вопросов, отдельные dev/test/regression-группы, слепая CSV-таблица человеческой разметки и скрипт метрик. Это кандидаты для gold dataset, а не уже проверенная человеком истина. Инструкция и ограничения: [evals/README.md](../evals/README.md). Скрипт `scripts/eval-judge.py` по умолчанию показывает только план; внешние запросы выполняются с `--run`. Он использует рабочий оценщик и не передаёт модели gold-разметку. Для инфраструктурной проверки без сети есть `--self-test`, результаты которого не являются оценкой модели.
